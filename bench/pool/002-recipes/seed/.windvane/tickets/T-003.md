# T-003: Sum recipes into one shopping list
Depends on: T-002.
Touches: recipes.py, tests/test_shop.py.

## Goal
Cooking three recipes in a week means adding up their flour by hand, across `g` and `kg`. One list to take to the
shop is what the user wants.

## Scope
`python3 recipes.py shop <file>...` reads every recipe given and prints one line per thing to buy, summed across
the recipes. An optional `--serves N` scales every recipe to N servings first, as `scale --serves N` does.

## Done when
- `shop a.txt b.txt` prints one line per ingredient, `- <quantity> <unit> <name>` (or `- <quantity> <name>` with no unit), sorted by name ignoring case, and nothing else.
- ingredients with the same name (ignoring case, shown as first written) and the same unit are summed into one line, across files and within one.
- `g` and `kg` count as one unit, shown in `g` below 1000 g and in `kg` from 1000 g up (`600 g flour` and `1 kg flour` make `- 1.6 kg flour`; `0.5 kg rice` alone shows as `- 500 g rice`); `ml` and `l` the same way. The same name in other units gets one line per unit, in the order the units first appear.
- `shop a.txt b.txt --serves 2` scales each recipe to 2 servings before summing.
- `shop` with no file prints a usage line to stderr and exits 2; a missing or broken recipe file gives the same error and exit code as `show`, and prints nothing on stdout.
- tests in `tests/test_shop.py` cover each point.
