# T-002: Filter rows by a condition
Depends on: T-001.
Touches: csvtool.py, tests/test_filter.py.

## Goal
A user often wants only some rows of a file: one category, the amounts over a limit. Today they open a spreadsheet
for that; csvtool should give them the rows as a CSV they can save or pipe on.

## Scope
`python3 csvtool.py filter <file> <condition>`, a condition being `<column><op><value>` with no spaces around the
operator, the op one of `=`, `!=`, `<`, `>`, `<=`, `>=`. `=` and `!=` compare text exactly; `<`, `>`, `<=` and `>=`
compare numbers (as T-001 defines them), and a row whose cell isn't a number doesn't match them.

## Done when
- `python3 csvtool.py filter data.csv category=food` prints the header row, then every row whose `category` is exactly `food`, in file order, as CSV.
- `amount>10`, `amount<=10`, `amount>=10`, `amount<10` and `category!=food` each give the rows a user would pick by hand; `amount>9.5` is numeric, so `10` matches and `9` doesn't.
- cells holding commas or quotes come out as valid CSV: reading the output back gives the same cells as the input rows.
- with no matching row, only the header row is printed, exit 0.
- a condition with no operator, or a numeric op with a value that isn't a number (`amount>abc`), prints `error: bad condition: <condition>` to stderr and exits 2.
- a column the header doesn't have prints `error: no column: <column>` and exits 1, and a file that can't be read prints `error: cannot read <file>` and exits 1, as for `sum`.
- tests in `tests/test_filter.py` cover each point.
